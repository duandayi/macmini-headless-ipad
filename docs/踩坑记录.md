# 踩坑记录（2026-10-27 实测）

做这套东西时撞到的所有坑，按时间顺序。后来者照着看能省几小时。

---

## 一、开机后 iPad 死活连不上

**现象**：关机再开机，iPad 一片黑，怎么等都没画面。

**根因**：登录项被整批清空（连无关的 App 也没了）。BetterDisplay 和 SideLinker 都没启动，
系统后来自己把 Sidecar 连上了，但**没有镜像源**，所以是黑屏。

**教训**：不要依赖"登录项"当唯一启动手段。本项目改成 launchd LaunchAgent（`RunAtLoad`），
即使登录项被清也能起。

---

## 二、随航单独撑不起一块屏

**实验**：只保留 Sidecar，关掉所有虚拟屏，连续观测 65 秒。

**结果**：Sidecar 全程 `offline`。没有虚拟屏 = 没有镜像源 = 黑屏。

**结论**：虚拟屏是必需品。但**不必**是付费的 BetterDisplay。

---

## 三、自写虚拟屏时 `initWithDescriptor:` 一直返回 nil

这一步卡了很久，踩了三层：

### 1. 段错误（先撞上的）
用 `NSInvocation` 传参数，`initWithWidth:height:refreshRate:` 的真实签名是
`uint32, uint32, double`，我按 `NSUInteger` 传，ABI 错位 → `Segmentation fault: 11`。

**解法**：直接声明 `@interface` 用消息发送，别用 NSInvocation 手搓参数。

### 2. 类找不到（误判）
一开始用 `NSClassFromString(@"CGVirtualDisplay")` 拿类，dump 方法列表都正常，
所以一度以为"类的名字是对的，只是 init 失败"。

**真正的坑在下面。**

### 3. 身份冲突（真正的根因）
我为了"完全对齐"，把 `vendorID / productID / serialNum` 照抄了 BetterDisplay 的
`2198 / 18970 / 3491416317`。结果：macOS 认为这是同一块屏，拒绝创建。

WindowServer 日志（`log show --predicate 'eventMessage CONTAINS "virtualdisplay"'`）：

```
VirtualDisplay(CGXVirtualDisplayCreate) no displayID available
-[VirtualDisplayClient pluginWithOptions:]: spawnProxy message error kr=0x5 ((os/kern) failure)
```

**解法**：换成独立身份 `0x4D41 / 0x4944 / 0x49504144`（"MA"/"ID"/"IPAD"），立即成功。

```
[3] display=0x7c31478b60
[4] apply=1
SUCCESS
```

## 四、新建/切换虚拟屏会把随航打回 1x

**现象**：虚拟屏一建，iPad 上的字立刻变糊。

**原因**：显示器拓扑变化后，macOS 把 Sidecar 切到了 1x 模式（`Resolution` = `UI Looks like`）。

**解法**：

```bash
displayplacer "id:<iPad屏ID> res:1323x919 hz:60 color_depth:4 scaling:on"
```

判断标准：**`Resolution` 应该是 `UI Looks like` 的 2 倍**。

---

## 五、两个管理者会打架

虚拟屏如果既被 LaunchAgent（`KeepAlive`）拉起、又被守护脚本 `pgrep` 后拉起，
会出现"第二个实例创建失败"的循环（身份冲突）。

**解法**：只让**一个**管理者拥有它。本项目由 launchd 独占，守护脚本只监控、不抢。

---

## 六、其他

- `system_profiler SPDisplaysDataType` 里 Sidecar 那块屏**没有 `Online:` 字段**，
  用 `Main Display` / `Connection Type: AirPlay` 判断更可靠（我一开始用 Online 判断，误判了）
- SideLinker 的本地 API 是 `http://127.0.0.1:14792`，所有请求都要 `Authorization: Bearer <token>`
- 有线随航（USB-C）比无线稳得多：`connection_type` 会变成 `wired`
